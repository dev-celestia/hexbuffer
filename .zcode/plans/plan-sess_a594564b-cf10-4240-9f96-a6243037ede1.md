## Fix: make Cmd+A work via keyboard shortcut in all editors

**Why it's broken (from investigation):** The app defines no menu (`tauri.conf.json` has no `menu` key, no menu code in `src-tauri/src/`), so it runs with Tauri v2's default macOS menu. That menu's Edit submenu contains a native "Select All" item whose Cmd+A accelerator is consumed at the AppKit level before the WKWebView receives the keydown — Monaco never sees the event, so nothing happens. Proof: `src/pages/notes/hooks/use-notes-page.ts:138` already contains a per-editor Cmd+A workaround someone added for the Notes page; the same failure affects every other Monaco editor (repeater, HTTP history, intercept, intruder, etc.). No frontend code blocks Cmd+A.

**Fix (Rust-only, one place):** Define a custom macOS app menu that reproduces the default but **omits the native Select All item** from the Edit submenu. With no menu item claiming Cmd+A, the key falls through to the webview as a normal keydown and Monaco's built-in select-all handles it in every editor at once.

### Implementation

In `src-tauri/src/setup.rs` inside `init()`, gated with `#[cfg(target_os = "macos")]`:

1. Build the menu with `tauri::menu::{MenuBuilder, SubmenuBuilder, PredefinedMenuItem, MenuItemBuilder}`:
   - **App submenu**: About, Separator, Services, Hide, Hide Others, Show All, Separator, Quit (all `PredefinedMenuItem`).
   - **Edit submenu**: Undo, Redo, Separator, Cut, Copy, Paste — **no Select All**.
   - **Window submenu**: Minimize, Zoom, Separator, Close (predefined).
2. Apply with `app.set_menu(Some(menu))`.

Other native edit accelerators (Cmd+C/X/V/Z, Cmd+S handlers in page hooks) keep working; only the swallowing Select All accelerator is removed.

### Verification

1. `cd src-tauri && cargo run` (or `pnpm tauri`), open Repeater, click in the request editor, press Cmd+A — all editor text (not the whole page) highlights.
2. Repeat in HTTP history detail view and Intercept.
3. Confirm the menu bar still renders correctly (App/Edit/Window menus intact, no "Select All" entry).
4. Confirm Cmd+C / Cmd+V and the page-level Cmd+S handlers still work.

The redundant Notes-page workaround stays as-is (harmless).
