Each store is a standalone Zustand store created via `create()` and typically wrapped with the `persist` middleware to survive page reloads. The `automation/` sub-package follows a slice pattern: a central `index.ts` composes multiple slice creators (`workflows-slice`, `execution-slice`, `logs-slice`, `runtime-slice`, `live-traffic-slice`) into one `useAutomationStore`, with shared types in `types.ts` and constants in `constants.ts`. The `history/` sub-package groups related HTTP and WebSocket history stores behind an `index.ts` barrel that re-exports each store individually. Flat stores at the root (e.g., `app.ts`, `jwt-store.ts`, `tools.ts`, `nav.ts`, `filter.ts`) own single-domain state such as proxy lifecycle, JWT tooling, navigation, and filtering. Stores that interact with the Tauri backend use `invoke()` from `@tauri-apps/api/core` directly inside async actions. Persistence is configured per-store via `partialize` to select only serializable fields and a custom `merge` function to validate/normalize persisted data on load.
