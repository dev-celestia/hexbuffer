The module is organized as a top-level page container split into two parallel sub-features — `http-history/` and `websocket-history/` — each following an identical internal layering: an `index.tsx` page component, a `hooks/` directory with React hooks (`use-*-history-page`, `use-*-query`, `use-*-detail`, `use-*-table`), a `components/` directory for view/UI pieces, an `api.ts` file wrapping Tauri `invoke` calls, and a `utils.ts` helper. A shared `components/target-selector/` dialog is reused across both features to select monitoring targets. Each page composes a `TabbedPageLayout` from `@/components/tabs-layout` driven by a custom hook that derives tabs from active targets, pinned items, or groups. Data flows through Zustand stores under `@/stores/history` (e.g. `useHttpHistoryQueryStore`, `useWebSocketHistoryQueryStore`, `usePinnedRequestsStore`, `useGroupsStore`) and `@/stores/target`. The `inspector.tsx` component provides a reusable accordion-based key-value inspector used by both HTTP and WebSocket detail views. Dependency direction is strictly inward: pages → hooks → api/utils → Tauri backend; UI components depend only on `hexbuffer-ui`, `@phosphor-icons/react`, and shared lib utilities.
