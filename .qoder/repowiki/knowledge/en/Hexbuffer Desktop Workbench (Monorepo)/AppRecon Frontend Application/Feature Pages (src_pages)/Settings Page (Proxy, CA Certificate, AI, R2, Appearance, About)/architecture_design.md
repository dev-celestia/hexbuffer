The module follows a tabbed-settings layout pattern centered around a single `useSettingsPage` hook (`hooks/use-settings-page.ts`) that owns all mutable state and side effects — it calls Tauri backend commands via `@tauri-apps/api/core` `invoke`, reads/writes OS credential stores, polls proxy status with `setInterval`, and exposes a flat `SettingsPageState` object to child components. `index.tsx` is the route entry that renders `<SettingsLayout>` passing this shared state. `settings-layout.tsx` drives tab navigation via `react-router-dom` search params (`?tab=...`), maps each category to a dedicated tab component under `components/`, and animates transitions with a keyed content container. `settings-sidebar.tsx` defines the `SettingsCategory` union type and renders the left nav. Each tab component (`general-settings-tab`, `ca-certificate-settings-tab`, `ai-settings-tab`, `r2-settings-tab`, `automation-settings-tab`, `appearance-settings-tab`, `about-settings-tab`) consumes only the subset of `SettingsPageState` it needs, keeping them stateless presentational layers. Shared UI primitives `SettingsGroup` and `SettingsRow` live in `components/settings-group.tsx`, and static configuration (AI providers/models, installation guides, troubleshooting) lives in `constants.ts`. Cross-cutting concerns are delegated outward: updater logic via `useUpdater` from `@/hooks/use-updater`, proxy store via `@/stores/app`, browser automation artifacts via `@/stores/browser-automation`, and CA certificate operations via `@/pages/live-traffic/http-history/api`.
