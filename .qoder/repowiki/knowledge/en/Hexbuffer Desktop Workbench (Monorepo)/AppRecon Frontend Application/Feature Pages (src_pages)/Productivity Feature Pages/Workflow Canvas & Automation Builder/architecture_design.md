The module is organized as a React page (`index.tsx` exporting `AutomationPage`) wrapped in `ReactFlowProvider`, composing a resizable panel layout (horizontal canvas + optional node-config panel, vertical split for execution log) driven by the `useAutomationPage` hook. State lives in an external Zustand store (`@/stores/automation`); the hook wires tabs, active workflow selection, template dialog, and bridge refs to the canvas.

- `components/` holds presentational React Flow pieces: `workflow-canvas.tsx` (the `<ReactFlow>` surface), context menus, toolbar, palette, node config panel, execution log, and templates dialog.
- `hooks/use-workflow-canvas.ts` encapsulates all React Flow state (nodes, edges, selection, context menus, drag-and-drop) behind a `WorkflowCanvasBridge` interface exposed via ref.
- `lib/` contains pure logic: `node-factory.ts` creates nodes from `NODE_TYPE_REGISTRY`, `canvas-definitions.ts` maps type strings to React components (`TriggerNode`, `ConditionNode`, `ActionNode`) and edge types, `edges.ts`, `condition-evaluator.ts`, `workflow-runtime.ts`, `workflow-readiness.ts`, and per-category profile/warning/capability helpers.
- `nodes/` defines the three concrete React Flow node renderers plus shared card chrome (`node-card-menu`, `node-delete-button`, `node-capability-badge`, `node-runtime-status`). Config UI lives under `nodes/nodes-config/` split by category.
- `types.ts` declares the canonical domain model (`AutomationNodeType`, `NodeConfig`, `WorkflowDef`, `WorkflowRun`, etc.).
- `node-type-registry.ts` and `constants.ts` together form the single source of truth for every node type's metadata (label, icon, default config, description).

Dependency direction is one-way: components → hooks → lib → node renderer components; the registry and constants are consumed everywhere but never mutated.
