Each `.rs` file under `src/commands/` defines one or more `#[tauri::command]` functions that serve as the IPC boundary between the Rust backend and the Tauri frontend. The `mod.rs` re-exports every submodule (`browser`, `cert`, `chat_sessions`, `collaborator`, `history`, `intercept`, `invoker`, `mock_forge`, `proxy`, `r2`, `regression`, `repeater`, `storage`, `vpn`, `api_collection`) so they can be registered with Tauri at app startup. Commands are thin adapters: they parse typed request structs (serde `Deserialize`), call into the corresponding `crate::*` domain modules (e.g. `crate::browser`, `crate::proxy`, `crate::ai`, `crate::db::repository`), and return serializable response structs (`Serialize`). Long-running or concurrent operations (browser crawling, invoker attacks) use `tokio::spawn` and share state through Tauri's `State<'_, ...>` mechanism backed by `Arc<Mutex<...>>` or `AtomicBool` cancellation flags. Cross-cutting concerns like process lifecycle, database access, and event emission go through shared types such as `BrowserProcessState`, `AiBrowserState`, `HistoryBridge`, and `Database` injected via `State`. The `ai.rs` module is a pure re-export shim delegating all logic to `crate::ai`.
