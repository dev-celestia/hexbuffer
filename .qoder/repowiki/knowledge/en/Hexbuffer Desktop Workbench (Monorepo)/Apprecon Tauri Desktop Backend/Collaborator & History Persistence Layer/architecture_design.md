Two sibling modules share the same persistence concern:
- `collaborator/mod.rs` re-exports `state` and `types`. `types.rs` holds all serde-serializable DTOs for collaborator servers, payloads, interactions, dashboard stats, and request/response shapes. `state.rs` defines `CollaboratorPollingState`, a process-wide `Arc<Mutex<HashMap<String, JoinHandle<()>>>>` used to track active polling tasks per collaborator identifier.
- `history/mod.rs` exposes `HistoryBridge`, a thin wrapper around a `Database` instance (from `crate::db::repository`). It provides CRUD methods grouped by domain: proxy logs, WebSocket connections/messages, AI browser sessions/pages/logs/insights, documents, stashes/endpoints, contexts, chronicle logs, chat sessions/messages, and collaborator entities. Each method delegates to the corresponding `Database` method and maps errors via `.map_err(|e| e.to_string())`.
- Dependency direction is one-way: `history` imports types from `collaborator` (for collaborator-related records) and from other crates (`ai::types`, `commands::browser`, `proxy::state`, `db::repository`), while `collaborator` has no internal dependencies beyond std and tokio.
