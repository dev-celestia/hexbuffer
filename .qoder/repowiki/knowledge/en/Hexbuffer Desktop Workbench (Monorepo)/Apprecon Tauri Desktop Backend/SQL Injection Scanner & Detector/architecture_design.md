The module is organized as a thin Tauri command layer (`mod.rs`) exposing three async commands — `start_sqli_scan`, `stop_sqli_scan`, and `get_sqli_scan_state` — which orchestrate the core `SqliDetector` from `detector.rs`. `detector.rs` owns HTTP request construction (via `reqwest::Client`), baseline response capture, per-parameter technique iteration, and DBMS fingerprinting. Payloads are static and DBMS-specific, held in `payloads.rs` through `SqliPayloads` and `PayloadSet` structs with a `get_payloads(technique, dbms)` accessor; detection heuristics live in the `SqliChecker` helper. All shared data types (scan config, parameters, progress events, vulnerability records, extraction results) are defined in `types.rs`, including the thread-safe `SqliScanState` backed by `Mutex<HashMap<String, Arc<AtomicBool>>>` for cooperative cancellation. The dependency direction is strictly one-way: `mod.rs` → `detector.rs` → `payloads.rs` + `types.rs`; there is no cross-import between `detector` and `payloads` beyond what `types.rs` re-exports.
