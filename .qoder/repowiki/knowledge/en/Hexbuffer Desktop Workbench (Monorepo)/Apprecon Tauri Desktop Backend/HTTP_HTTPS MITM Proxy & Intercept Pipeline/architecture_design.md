The module is a self-contained Tauri-side proxy pipeline organized around `hexbuffer_proxy::ProxyBuilder`. `mod.rs` owns process-level lifecycle: static `OnceLock` fields hold the shutdown channel, enabled flag, and active port; `run()` boots a tokio runtime, binds a TCP listener with fallback-port logic, constructs a `CertificationAuthority` from `ca.rs`, and wires `AppHandler` as both an HTTP handler and a WebSocket handler.

- `lifecycle.rs` implements `HttpHandler` and `WebSocketHandler` for `hexbuffer_proxy`. Each HTTP transaction is tracked in an in-memory `Ctx` stored in `pending_ctxs`; `handle_request` optionally delegates to `mock_forge::try_intercept` before applying intercept-mode logic (pause → poll `ProxyState` until an action arrives). `handle_response` applies response interception similarly, then delegates persistence to `completion::save_and_emit`.
- `state.rs` holds the shared `ProxyState` (a `Mutex<ProxyStateInner>`) containing recorded `ProxyRecord`s, paused requests, intercept mode, scope/bypass patterns, and per-tab capture configuration. It exposes filtering (`get_records_filtered`) and tab-scoped forwarding helpers.
- `types.rs` defines all serializable domain structs (`ProxyRequest`, `ProxyResponse`, `ProxyRecord`, WebSocket connection/message records, filters) used across the pipeline and emitted over Tauri events.
- `websocket.rs` parses WS targets from URIs and `Host`/`x-forwarded-proto` headers; `lifecycle.rs` uses it to map frames to connection IDs and emit `websocket-message` events.
- `mock_forge.rs` is an early-exit interceptor that matches against configured routes, applies chaos latency/error-rate rules, logs to `MockForgeState`, and returns a synthetic `RequestOrResponse` before normal proxying.
- `ca.rs` manages the CA certificate/key pair under `.hexbuffer` in the app data directory, regenerating on demand.
- `utils.rs` provides OS-level port management (`lsof` + `kill`), body re-encoding via `hexbuffer_proxy::decoder`, and captive-portal bypass detection.

Dependency direction is one-way outward: `lifecycle` → `state`, `types`, `completion`, `mock_forge`, `websocket`; `mod.rs` orchestrates startup and exposes only the public surface (`run`, `stop`, `set_proxy_enabled`, `encode_body`, `ensure_port_free`). Cross-cutting concerns like DB persistence and automation ingestion are delegated to `crate::HistoryBridge` and `crate::automation` modules outside this scope.
