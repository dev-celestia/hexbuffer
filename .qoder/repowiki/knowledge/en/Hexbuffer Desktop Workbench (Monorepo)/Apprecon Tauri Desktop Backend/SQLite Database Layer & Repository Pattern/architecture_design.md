The module is split into two top-level parts: `schema.rs` holds all DDL as raw SQL string constants (one per feature area: HTTP logs, WebSocket, documents, AI browser, collaborator, AI chat, regression, stashes, contexts, chronicle, mock forge), and `repository/` implements the data access layer. The central `Database` struct in `repository/mod.rs` wraps a `Mutex<rusqlite::Connection>` to provide single-connection concurrency safety, exposes `new`, `close_connection`, `reopen_and_init`, and an `init` method that enables foreign keys, sets WAL journal mode, runs every `CREATE TABLE IF NOT EXISTS` constant, then applies incremental `ensure_column` migrations for schema evolution. Each domain (ai_browser, api_collection, chat_sessions, collaborator, documents, proxy_logs, regression, websocket, mock_forge) lives in its own file and extends `Database` with methods returning `SqlResult<T>`. Shared DTOs (`types.rs`) define serializable record structs used across repositories. Dependency direction is one-way: repositories depend on `schema` constants and `rusqlite`; nothing inside `db` depends on Tauri commands except where types are re-exported from `crate::commands`.
