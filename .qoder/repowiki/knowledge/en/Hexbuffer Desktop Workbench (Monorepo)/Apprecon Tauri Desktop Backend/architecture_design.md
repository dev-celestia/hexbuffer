The crate is a Tauri v2 application (`hexbuffer`) whose `src/lib.rs` re-exports every feature module (`ai`, `automation`, `browser`, `collaborator`, `commands`, `db`, `history`, `port_scanner`, `proxy`, `sqli`, `tools`) so they share one process. Cross-module communication follows a consistent pattern: each feature exposes Rust functions that are registered as Tauri commands via the `commands/` layer, which then call into the corresponding domain module. Shared state flows through two cross-cutting concerns — the `collaborator` module's `HistoryBridge` (a thread-safe bridge over the `db_layer`'s SQLite repository) used by proxy, browser, AI, and automation to persist logs and sessions, and the global app state managed in `app_wiring` (tray, CDP browser process, updater). External binaries (`binaries/ai-engine`, `binaries/coding-agent`) are bundled and launched as child processes, while `resources/ghidra/*` Java scripts are embedded as native resources. The build pipeline uses `tauri-build` + `build.rs`, with the frontend served from `../dist` during dev and bundled via `tauri.conf.json` (updater endpoint, external bin declarations, icons, and platform-specific bundling).
