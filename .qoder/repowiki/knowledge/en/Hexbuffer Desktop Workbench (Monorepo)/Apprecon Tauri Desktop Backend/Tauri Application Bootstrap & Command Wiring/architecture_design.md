The module is the Tauri application entrypoint split across focused files:
- `main.rs` declares modules, defines a shared `log()` helper that writes timestamped lines to both stderr and `/tmp/hexbuffer.log`, sets a panic hook, configures Tokio worker threads, and constructs the `tauri::Builder` with all plugins and the full `invoke_handler!` macro listing every hexbuffer command.
- `setup.rs` performs one-time initialization: optional desktop updater plugin, database creation at `app_data_dir/hexbuffer.db`, CA directory setup, and registration of all long-lived singletons via `app.manage()` (ProxyState, InvokerState, PortScanState, BrowserProcessState, AiBrowserState, SqliScanState, CollaboratorPollingState, AutomationRuntimeState, Database, HistoryBridge, VpnState, MockForgeState). It also spawns async tasks for update checks and a splash-screen fallback timer.
- `tray.rs` builds the system tray menu with navigation items using `nav:`-prefixed IDs that trigger client-side routing via `window.eval("window.location.href = ...")`.
- `app_commands.rs` exposes small Tauri commands (`show_main_window`, `safe_start_dragging`, `get_cdp_targets`, `open_cdp_browser`) extracted from main to keep it readable; `open_cdp_browser` probes port occupancy, kills existing Chrome instances on Unix, and launches Chrome/Chromium with CDP flags.
- `types.rs` holds shared serde-serializable DTOs (`DocumentRecord`, `PaginatedResponse<T>`, `ProxySummaryRow`, `TreeNode`, `TreePath`, `StashRecord`, `StashEndpointRecord`, `ContextRecord`, `ChronicleLogRecord`) used across commands.
- `lib.rs` re-exports public types and functions from the `hexbuffer` crate so `main.rs` can reference them as `hexbuffer::...` in the `invoke_handler!` list.
Dependency direction is strictly inward: `main` → `setup`/`tray`/`app_commands` → `hexbuffer` crate; no cross-dependencies between sibling files except through `crate::log`.
