# Invoker & High-Speed Fuzzer

**Invoker** is Hexbuffer's high-speed parameter fuzzing and automated request injection engine. It allows developers, QA engineers, and security auditors to test how web applications handle unexpected inputs, boundary cases, high volumes of requests, dictionary attacks, and automated vulnerability payloads.

---

## What is Parameter Fuzzing?

Fuzzing involves marking specific parameter locations within an HTTP request template (such as URL query parameters, form fields, headers, cookies, or JSON values) and injecting a series of test inputs (payloads) to analyze how the target server reacts in terms of status codes, response lengths, error patterns, and latency variations.

---

## Attack Modes

Invoker provides four distinct execution strategies tailored to different testing objectives:

| Attack Mode | Description | Ideal Use Case |
| :--- | :--- | :--- |
| **Sniper** | Uses a single payload set. Injects payloads into one marked position at a time, testing each position sequentially. | Parameter-by-parameter vulnerability scanning (e.g., SQLi, XSS, Path Traversal). |
| **Battering Ram** | Uses a single payload set. Injects the identical payload into all marked parameter positions simultaneously. | Testing multi-field consistency (e.g., username & password matching). |
| **Pitchfork** | Uses multiple payload sets (one per marked position). Steps through lists in parallel synchronously. | Testing paired credentials (e.g., list of users alongside corresponding passwords). |
| **Cluster Bomb** | Uses multiple payload sets. Tests every possible permutation (Cartesian product) across all marked positions. | Exhaustive credential brute-forcing and multi-parameter combinatorial testing. |

---

## Payload Sets & Sources

Hexbuffer supports flexible payload configuration:

- **Built-in Wordlists**: Common injection strings, special characters, directory discovery lists, numeric ranges, and error triggers.
- **Custom Wordlists**: Import custom `.txt` or `.csv` dictionary files.
- **Dynamic Generators**:
  - Sequential or random numeric ranges (e.g., IDs from `1000` to `5000` with step `1`).
  - Character brute-force sets (custom character ranges and length limits).
  - Dates, timestamps, and UUID generators.
- **Payload Processing Rules**: Apply URL encoding, Base64 encoding, prefix/suffix additions, or hashing transformations to payloads before transmission.

---

## High-Throughput Engine & Concurrency Controls

Powered by a multi-threaded Rust execution core, Invoker delivers high-speed request throughput while giving you precise control:

- **Thread Concurrency**: Configure the number of parallel worker threads.
- **Rate Throttling & Delays**: Set millisecond delay intervals between requests to avoid triggering web application firewalls (WAF) or overwhelming staging servers.
- **Auto-Pause & Retry**: Automatically pause on connection drops or rate-limit responses (HTTP `429 Too Many Requests`).

---

## Result Analysis & Multi-Layout Inspector

As the attack runs, Invoker populates a real-time results table:

- **Sorting & Metrics**: Sort results by Status Code, Response Length, Latency, or Extracted Regex Matches.
- **Pattern Extractors**: Configure regex or JSONPath extractors to pull out specific tokens, error strings, or reflected text in response bodies.
- **Dynamic Full-Width & Maximized Inspector**: Expand the results inspector to full-width or maximized mode to analyze differences between baseline and anomaly responses without leaving the view.
- **Send to Repeater / Comparer**: Right-click any attack result to inspect it in Repeater or compare it with a baseline response in Monaco Comparer.

## Step-by-Step Workflow

1. **Load Base Request**: In **Live Traffic** or **Repeater**, right-click a request and select **Send to Invoker** (`Cmd+I` / `Ctrl+I`).
2. **Set Positions**: Highlight the values you want to test and click **Add Marker `§`** (e.g., `id=§100§`).
3. **Select Attack Mode**: Choose between Sniper, Battering Ram, Pitchfork, or Cluster Bomb.
4. **Define Payloads**: Assign wordlists or generators to each payload position.
5. **Start Attack**: Click **Start Attack** and monitor execution progress, status code distributions, and flagged anomalies.
