# Visual Workflows & Pipeline Automation

The **Workflows** module is a visual, node-based automation canvas powered by `@xyflow/react`. It enables you to design automated event pipelines, linking incoming network proxy triggers or schedules to custom processing steps, assertions, notifications, or external scripts without writing complex glue code.

---

## Node Types & Building Blocks

Workflows are built by dragging, dropping, and connecting nodes on the interactive canvas:

### 1. Trigger Nodes
- **HTTP Traffic Trigger**: Fires when an incoming request matches a specific URL path, method, domain, or status code.
- **WebSocket Trigger**: Fires on specific incoming or outgoing WebSocket message frames.
- **Timer / Cron Trigger**: Executes pipeline flows periodically (e.g., every 5 minutes).
- **Manual / AI Trigger**: Executed on-demand via a button click or AI agent command.

### 2. Action Nodes
- **Request Replayer Node**: Dispatches an HTTP request using dynamic inputs extracted from previous nodes.
- **Script Node**: Executes custom JavaScript functions to transform payload data or compute dynamic cryptographic signatures.
- **Extract Node**: Uses regex, JSONPath, or CSS selectors to capture token values or IDs from response bodies.
- **Notification Node**: Triggers desktop OS notifications, logs custom events, or sends external webhook alerts.

### 3. Logic & Assertion Nodes
- **Conditional Branch (If/Else)**: Evaluates response metrics, status codes, or header values to route execution down different branches.
- **Assertion Node**: Verifies target criteria (e.g., status == 200, response time < 500ms, JSON schema matches) and flags failures.

---

## Creating Your First Workflow

1. Open **Workflows** from the main sidebar.
2. Drag an **HTTP Trigger Node** onto the canvas and set the URL match pattern to `/api/v1/auth/login`.
3. Connect its output port to a **JSON Extractor Node** configured to extract `response.body.access_token`.
4. Connect the extracted token output to a **Request Replayer Node** that invokes protected endpoints using the fresh token.
5. Add an **Assertion Node** to verify the subsequent request returns HTTP `200 OK`.
6. Click **Run Workflow** to test interactively, or enable **Active Listener** mode for background monitoring.

---

## Common Use Cases

- **Automated Authentication Refresh**: Catch token expiration errors and automatically fire login requests to refresh session tokens in the background.
- **Real-Time Error Alerting**: Receive instant desktop notifications whenever an API endpoint returns unexpected `5xx` errors.
- **Multi-Step Integration Testing**: Execute end-to-end multi-step API journeys visually with full status feedback at each node.
