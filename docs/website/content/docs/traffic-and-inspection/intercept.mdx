# Active Traffic Interception

**Active Interception** gives you full control as a live gatekeeper between your client application (web browser, mobile app, CLI tool) and the destination server. Instead of passively recording traffic, interception pauses requests and responses in-flight, allowing you to inspect headers and parameters, modify payloads on the fly, and test how both client and server handle altered data.

---

## How Active Interception Works

```
Client  ──► [ Paused in Hexbuffer Intercept ] ──► (Modified Request) ──► Target Server
Client  ◄── (Modified Response) ◄── [ Paused in Hexbuffer Intercept ] ◄── Target Server
```

1. **Client Dispatches Request**: Your browser or API client sends an HTTP/HTTPS request.
2. **Hexbuffer Pauses Traffic**: When Intercept is active, the request is held before transmission.
3. **Inspect & Alter**: Modify headers, authentication tokens, JSON bodies, or form parameters in the rich editor.
4. **Action Executed**: Choose to **Forward** (transmit modified data), **Drop** (terminate the connection), or **Pass Through** remaining requests.

---

## Interception Modes & Controls

- **Intercept Requests**: Pause outgoing requests sent by the client.
- **Intercept Responses**: Pause incoming responses returned by the server before the client receives them.
- **Forward (`Cmd+Enter` / `Ctrl+Enter`)**: Dispatch the active request or response with your edits applied.
- **Drop**: Discard the in-flight packet, simulating a network timeout or dropped connection.
- **Pass Through**: Temporarily bypass interception for remaining queued traffic.

---

## Match Rules & Breakpoint Filters

Avoid getting overwhelmed by high-traffic web applications by setting targeted match rules:

- **Host & Domain Filter**: Only pause traffic directed to specific target domains (e.g., `api.example.com`).
- **Method Matching**: Target specific HTTP verbs (e.g., only intercept `POST` or `PUT` requests).
- **URL Path Patterns**: Match specific routes such as `/api/v1/checkout` or `/login`.
- **Response Status Matching**: Only pause responses matching specific status codes (e.g., `500 Server Error` or `403 Forbidden`).

## Common Use Cases & Testing Scenarios

### 1. Client-Side Restriction Bypasses
Test whether backend APIs properly validate inputs by removing read-only flags, bypassing disabled form inputs, or modifying hidden form fields that the frontend UI attempts to restrict.

### 2. Privilege Escalation & Role Tampering
Alter session cookies, user IDs, or role claims in transit to verify whether unauthorized users can perform administrative operations.

### 3. Server Error & Resilience Simulation
Drop critical requests or modify server error responses to evaluate whether your frontend displays graceful fallback UI or crashes unexpectedly.

---

## Best Practices

> [!WARNING]
> **Remember to Disable Interception**: Leaving interception active with pending paused requests will cause browser tabs or API clients to hang until forwarded or dropped!
